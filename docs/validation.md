- ケース装着時の接続安定性、RSSI、消費電流・電池持ち：未測定です。

## v0.10.0 — 実機確認中

- 左右を同じソースからビルドし、配布UF2と一致することを確認しました。右は535,100 bytes、範囲 `0x26000..0xA8B00`、左は349,460 bytes、範囲 `0x1000..0x56600` です。設定・ブートローダーの領域に重ならず、ローカルの個人パスも含みません。
- 保存スキーマは左右とも従来の `0xA805CEFB` です。Vialの物理ロックは保存内容を変えないため、そのfeatureだけをスキーマ計算から除いています。
- **自動テスト232件が成功**しました。RMKの193件は各プロセスを分け、左右の再接続・入力同期・登録解除、USB／BLEの入力解除、Vialの物理解除と各書換経路を検査しています。ほかはPAW通信・感度・スケジュール20件、LED10件、初期配列9件です。
- Vial本体のキーコード処理でも、配布プリセットの392セルとエンコーダ28方向を読み込めることを確認しました。
- LEDの極性と左のRGB配線は基板・既存設定で確認しました。点滅回数、消灯、低電池の閾値と表示抑制、PWM送信データは自動テスト済みです。低電池の実際の点滅と消費電流はまだ測っていません。

実機では次を確認しました。

- 左右をUSB識別情報で区別し、更新前のファームと右のVial設定を保存してから、配布UF2を書き込みました。転送後は左右とも通常のUSB機器として起動し、右のVial版応答は `0x00000A00`（v0.10.0）でした。
- 392セルを読み戻し、以前に割り当てられていたキー、エンコーダ28方向、マクロ、感度などの設定が保持されていました。差分は、Layer 6で空いていた7枠に新しい接続操作が入ったことだけです。保存済みの項目を既定値へ重ねる復元処理によるものです。
- 左右のキー入力と右トラックボールが動くことを操作で確認しました。左のRESETを1回押すと状態LEDが点滅し、左の入力が自動で復帰しました。通常時は消灯しています。
- ログでも左の切断後に再接続と通知登録が行われ、PCとの保存済みBLE接続も復帰しました。Macから右の残量96％の読み出しと通知登録がありました。
- 右のVialがロック状態で起動し、キーテスターの読み出しを拒否することを確認しました。解除キーの応答は右のY＋Backspaceです。
- 右のUSBを抜いたBLE運用で、待機後に操作して復帰できたとの確認を得ました。使用者による操作確認で、正確な待機時間や最初の入力レポートは計測していません。

### 実機で残る確認

| 確認 | 合格条件 |
| --- | --- |
| クリック・エンコーダ・低電池表示 | 各入力が動き、低電池の短い表示が実際のLEDに出る |
| Vialの物理解除 | 指定キーを進捗バーが完了するまで押すと解除され、キーテスターに実際の押下が表示される |
| 出力の切り替え | BLEでクリックを押したままUSBへ切り替えても、旧PCに押下が残らない |
| 左の再接続 | 切断中から押し続けたShiftが復元され、最初の短い入力が一度だけ届く |
| 左右の登録解除 | 左がいる場合といない場合の両方で解除・再登録できる |
| 復帰時の最初の入力 | USB／電池のみで5分の待機時間を計測し、最初のキーとボールの動きが欠けないことを確認する。BLEで待機後に復帰すること自体は操作確認済み |
| PCのスリープ | PCが復帰後、古い入力がまとめて届かず、入力を続けられる |
| 複数セット | 片側を切っても別のセットに接続しない |
| 消費電流・電池持ち | 電池側で動作中／待機中の電流と実際の連続使用時間を測る |

電流の実測には測定器が必要です。電圧からの残量推定や自動テストから、実測した電池寿命を算出したことにはしません。

## v0.9.7

待機と復帰を見直した版です。以下は今回の確認結果です。

- 右のビルドと配布UF2の一致を確認しました。書き込み範囲は `0x26000..0xA6000`、アプリは524,244 bytesで、ブートローダー・設定領域に重なりません。開発PCのローカルパスを含まず、設定の保存形式は `0xA805CEFB` のままです。左v0.9.0の配布ファイルは変更していません。
- GPIO読取スケジュール、感度、初期配列、電池サービス、AML、キー割当通知、スリープ、左右再接続、USB復帰の自動テスト177件が通りました。RMKの148件は各テストを別プロセスで実行しています。USBでは実際の送信ループに模擬エンドポイントを接続し、停止中の最初の入力、抜き差し、復帰しない場合の期限、出力先変更を再現します。
- PAW3222のGPIOスケジュールは、初めからLOW、待機中にLOW、LOW／HIGHのまま戻らない場合と、スリープ状態の切り替えを確認します。実電極・電波・電流の測定ではありません。

実機では次を確認しました。

- 右への書き込み後、通常USB機器として起動し、Vialで読み出せること。書き込み中のドライブ切断後に確認しています。
- 更新前後のVial保存データが一致すること。392キー、エンコーダ28方向、マクロなどの設定を保持しました。
- 左v0.9.0との接続と、保存済みのPC登録による暗号化BLE接続。Macから右の電池残量95％の読み出しと通知登録がありました。
- USB接続中、最後のボール操作の約5分後に `Entering sleep mode` と `PAW3222 idle: motion IRQ armed, sensor power retained` が記録されること。
- 待機中もVialの読み出しが完了し、保存設定が更新前と一致すること。
- その後の入力活動で `Waking up from sleep mode due to activity` と `PAW3222 awake` が記録されること。通常復帰でセンサーを初期化し直すログやID異常はありませんでした。

復帰前後の最初のキー・座標が抜けないことの操作確認、BLEだけでの復帰、PC自体のサスペンドからの復帰は、まだ確認結果を得ていません。長期間の接続安定性、消費電流と電池持ちも未測定です。

## v0.9.5

右側の電圧測定を有効にし、推定残量をBLE Battery Serviceへ反映する変更です。標準のBattery Serviceは右の1つだけにし、左の残量用サービスはCoreX独自のUUIDへ変更しています。左から右への残量受信は残していますが、PCの標準画面で左を個別表示する機能はありません。初期配列とトラックボールの処理、Bluetooth名 `Cornix TB` は変更していません。

右の測定入力は `P0_04`、分圧比は `2000 / 3000` です。`P0_31` をHighにして350 ms待ち、測定回路が安定してからADCを初期化します。接続時・読み出し時・通知の購読開始時にも、保存済みの測定値をBLEへ反映します。

実機を使わない検査では、次を確認しました。

- 右v0.9.5のビルドとUF2の検査。書き込み範囲は `0x26000..0xA5C00` で、ブートローダーと設定領域には重なりません。配布UF2と再ビルド結果の一致、開発PCのローカルパスを含まないことも確認しました。
- 設定の保存形式は `0xA805CEFB` のままです。左v0.9.0のファイルも変更していません。
- 既存の通信・配列などのテスト20件と、BLE Battery Serviceのテスト6件が通りました。後者は、キャッシュした残量の読み出し、左右のサービス定義、暗号化前のアクセスを電池情報だけに限定する条件を検査しています。

実機では、配布UF2を書き込んで次を確認しました。

- 右へのUF2書き込みと通常起動。
- 更新前後のVial保存データの一致。392セル、エンコーダ28方向、マクロなどの設定が保持されました。
- 登録し直したPCへ、保存済みのペアリング情報で暗号化接続が復帰すること。
- macOS 15.2（24C101）のBluetooth設定で、`Cornix TB` に98％と表示されること。画面のアクセシビリティ情報とシステム情報でも確認しました。
- MacがBLE経由で右の推定残量98％を読み出し、残量通知を購読すること。

USBを抜いた状態のキー入力・トラックボール操作と、切断・再接続後の残量表示は、同じ残量サービスを使う確認用ファームで確認しました。配布版では、そのファームから診断ログを削減しています。左からの残量値も開発中に受信を確認していますが、精度や推移は未検証です。

この更新ではGATTの構成が変わるため、PC側の登録削除と、キーボード側の対象PC枠の消去をしてから接続し直しています。キー配列や左右の登録を全消去する手順ではありません。[再登録の手順](usage.md#pc-の登録をやり直す)

残量は電圧からの推定値で、実容量や残り使用時間を測定するものではありません。放電に伴う割合の変化と精度、macOS 15.2以外のOSでの表示は未検証です。

## v0.9.3 の初期配列

右への UF2 書き込み、USB での通常起動、初期配列の適用と読み戻しを確認しました。392セルとエンコーダ28方向が配布する初期配列と一致しています。新しいキー位置、エンコーダの向きと Bluetooth 操作について、手で操作しての確認は完了していません。

初期配列は、2026-10-09に取得した[メーカー配布の初期キーマップ](https://docs.channel.io/jezailfunderjp/ja/articles/Cornix-%E6%97%A5%E6%9C%AC%E8%AA%9E%E3%83%9E%E3%83%8B%E3%83%A5%E3%82%A2%E3%83%AB-c1160246)を基にしています。通常キー・数字記号・エンコーダを純正の位置に対応させ、トラックボール用の操作と設定欄を加えています。

実機を使わない検査では、次を確認しました。

- 右 v0.9.3 のビルドが成功し、配布ファイルと再ビルド結果が一致すること。左 v0.9.0 のファイルは変更していません。
- UF2 がブートローダーと設定領域に重ならず、開発PCのローカルパスを含まないこと。
- 設定の保存形式が `0xA805CEFB` のままであること。
- 既存の Rust テスト11件と、初期配列の Python テスト9件が通ること。初期配列ファイルも生成結果と一致しています。
- Vial の仮想キーボードで初期配列ファイルを読み込み、再保存した392セルとエンコーダ28方向が元の配列と一致すること。既存マクロも保持されました。

このオフライン検査には、実機でのキー入力やBluetooth接続、UF2更新後の設定読み出しは含みません。

純正Cornixの無線ドングルとの接続と電池持ちは未確認です。v0.10.0には独自の短い状態LED表示を実装しています。純正の全点灯パターンの再現ではありません。配布ファームにはトラックポイントとタッチパッドの処理を含めていません。
